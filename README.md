## Задание 1

**На лекции рассматривались режимы репликации master-slave, master-master, опишите их различия.**

**Master-Slave (Мастер-Слейв):**

Это асимметричная конфигурация, при которой репликация данных идёт только в одном направлении — от мастера к слейву.

- **Master (Мастер)** — основной сервер базы данных, который принимает все запросы на изменение данных (INSERT, UPDATE, DELETE). Все операции записи выполняются только на этом сервере.
- **Slave (Слейв)** — вспомогательный сервер, который непрерывно копирует данные с мастера. С него обычно выполняются операции чтения (SELECT). Слейвов может быть несколько.

**Применение:**
- Распределение нагрузки на чтение (чтение со слейвов, запись на мастер)
- Создание резервных копий
- Обеспечение отказоустойчивости (если мастер падает, один из слейвов можно повысить до мастера)
- Тестирование новых конфигураций

**Особенность:** Запись на слейв по умолчанию запрещена (флаг read_only=1). Репликация может быть синхронной или асинхронной.

---

**Master-Master (Мастер-Мастер):**

Это симметричная конфигурация, при которой репликация данных идёт в обе стороны. По сути, это две настроенные друг на друга репликации master-slave.

- Оба сервера являются одновременно и мастерами, и слейвами друг для друга.
- Оба сервера принимают запросы и на чтение, и на запись.
- Изменения на любом из серверов автоматически реплицируются на другой.

**Применение:**
- Повышение доступности (Active-Active конфигурация)
- Если один узел падает, второй продолжает принимать и читать, и писать данные
- Распределение нагрузки на запись и чтение между двумя узлами

**Особенности и ограничения:**
- Требует осторожности при настройке
- При одновременном изменении одних и тех же данных на обоих узлах могут возникнуть конфликты
- Необходимо использовать уникальные auto_increment_increment и auto_increment_offset для избежания конфликтов первичных ключей
- Не все приложения подходят для такой конфигурации

---

**Ключевые различия:**

| Параметр | Master-Slave | Master-Master |
|----------|--------------|---------------|
| Направление репликации | Одностороннее (мастер → слейв) | Двустороннее (оба направления) |
| Запись данных | Только на мастер | На оба сервера |
| Чтение данных | Со слейва (или мастера) | С любого сервера |
| Количество мастеров | 1 | 2 (или более) |
| Отказоустойчивость | Требует ручного переключения | Автоматическая (оба активны) |
| Сложность настройки | Проще | Сложнее (риск конфликтов) |
| Риск конфликтов данных | Нет | Есть (требует дополнительной настройки) |

## Задание 2

**Выполните конфигурацию master-slave репликации. Приложите скриншоты конфигурации, выполнения работы: состояния и режимы работы серверов.**

### 1. Подготовка файлов конфигурации

**master.cnf**

```ini
[mysqld]
server-id=1
log-bin=mysql-bin
binlog_format=ROW
```
**slave.cnf**

```ini
[mysqld]
server-id=2
read_only=1
```

**master.sql**

```sql
CREATE USER 'repl'@'%' IDENTIFIED BY 'slavepass';
GRANT REPLICATION SLAVE ON *.* TO 'repl'@'%';
FLUSH PRIVILEGES;
```
**slave.sql**

```sql
CHANGE REPLICATION SOURCE TO
SOURCE_HOST='mysql_master',
SOURCE_USER='repl',
SOURCE_PASSWORD='slavepass',
SOURCE_SSL=1;
START REPLICA;
```

**Dockerfile_master**

```dockerfile
FROM mysql:9.3
COPY ./master.cnf /etc/mysql/conf.d/my.cnf
COPY ./master.sql /docker-entrypoint-initdb.d/start.sql
ENV MYSQL_ROOT_PASSWORD=12345
CMD ["mysqld"]
```

**Dockerfile_slave**

```dockerfile
FROM mysql:9.3
COPY ./slave.cnf /etc/mysql/conf.d/my.cnf
COPY ./slave.sql /docker-entrypoint-initdb.d/start.sql
ENV MYSQL_ROOT_PASSWORD=12345
CMD ["mysqld"]
```
